# Dependency classification

Updated: 2026-07-21

## Scope

This report classifies the packages flagged by the conservative codebase inventory and one previously identified misplaced type package. Import absence alone was not treated as deletion evidence.

## Changes applied

### Removed

| Package | Reason | Verification |
|---|---|---|
| `@types/recharts` | No source, config, script, or generated-tooling consumer. The project continued to typecheck and build with the installed `recharts` package after removal. | Clean install, TypeScript, ESLint, full unit tests, lesson content-standard tests, and production build passed. |
| `tw-animate-css` | No CSS import, Tailwind plugin registration, config reference, source import, or script consumer existed. Active animations are declared directly in `src/app/globals.css`. | Clean install, inventory, TypeScript, ESLint, tests, content-standard, and production build passed. |

Removing `@types/recharts` also removed its now-unneeded direct lockfile branch for `@types/d3-shape`.

### Moved from runtime dependencies to development dependencies

| Package | Reason |
|---|---|
| `@tailwindcss/postcss` | Loaded by `postcss.config.mjs` during CSS compilation; it is build tooling rather than application runtime code. |
| `shadcn` | Used as repository UI-generation tooling with `components.json`; generated application components do not require the CLI at runtime. |

Both tools remained installed during development/build validation. `npx shadcn --version` and resolution of `@tailwindcss/postcss` passed after the move.

## Validation

The proposed package graph was generated by npm rather than editing the lockfile manually. Validation then ran twice: once before committing the package files and once from the committed clean state.

```bash
npm install --package-lock-only --ignore-scripts --legacy-peer-deps
git diff --exit-code -- package.json package-lock.json
npm ci --ignore-scripts --legacy-peer-deps
npx shadcn --version
node -e "require.resolve('@tailwindcss/postcss')"
npm run inventory -- --write
npx tsc --noEmit
npm run lint
npm run test
npm run test:content-standard
npm run build
```

Results:

- committed manifest and lockfile are stable; npm regenerates no diff
- clean installation passed
- retained build and CLI tooling passed
- TypeScript passed
- ESLint passed
- full unit tests passed
- lesson content-standard tests passed
- production build passed
- no package version was upgraded or downgraded

## Interpreting the generated inventory

The conservative inventory can still flag packages loaded implicitly by frameworks, configuration files, shell hooks, CI, or type systems. The remaining reported names are documented above as verified retained packages, not open deletion tasks.
